# Customer Gym QR Implementation Plan

> Execute inline, one verified slice at a time.

**Goal:** Let customers record a gym visit from a QR in Settings.
**Architecture:** Private database functions validate a branch token and exact member identity; public RPC wrappers expose limited results. Reuse existing attendance and public-form styles.
**Tech Stack:** Next.js, React, Supabase Postgres, qrcode, PGlite.
**Spec:** docs/superpowers/specs/2026-11-17-gym-qr-design.md

- [x] Implement migration and RPC service, preserving RLS and preventing public member reads.

## Constraints and review

Gym only. No member directory or financial data in public responses. Use Malaysia date and database uniqueness for duplicate prevention. Handle unavailable branches and connections, invalid tokens, same-name members, repeat taps, and branch changes.
